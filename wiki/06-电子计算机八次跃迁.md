## 为什么用「电子计算机」而不是「电脑」

| 词 | 通常指 | 本文档为何不用 |
|---|---|---|
| **电脑** | 个人计算机（PC） | 缩小了对象 —— 八次跃迁追踪的是从 ENIAC 到 AI 工厂的完整谱系 |
| **电子计算机** | 从 ENIAC 起的完整技术谱系 | **本套文档统一用此口径** |

**电子计算机的代际划分**（中国教科书口径，与八次跃迁的前段对齐）：

| 代 | 时期 | 逻辑部件 |
|---|---|---|
| 第一代 | 1946–1957 | 电子管 |
| 第二代 | 1958–1965 | 晶体管 |
| 第三代 | 1966–1971 | 中小规模集成电路 |
| 第四代 | 1971– | 大规模、超大规模集成电路 |

## 八次跃迁

### 1 · 1945–1957｜电子管 / 晶体管 —— 确立「存储程序」

- **跃迁**：程序从「改接线」变成「存进机器」，与数据同构；电子管换成晶体管后体积与能耗骤降
- **影响**：「一台机器跑不同程序」成为可能，**软件第一次成为独立产业**；此后所有通用计算形态的根源都在这里
- **里程碑**：冯·诺依曼《EDVAC 报告初稿》（1945）、ENIAC（1946）

### 2 · 1958–1978｜集成电路 / ISA 商业化 —— ISA 成为商业契约

- **跃迁**：微处理器把 CPU 变成可量产商品；x86 用「向下兼容」把指令集变成长期契约（1978）
- **影响**：软硬件彻底解耦，OS 与应用可独立迭代；**「兼容优先于最优」从此成为整个 PC 产业的文化**，也决定了此后三十年谁的护城河更深

### 3 · 1985–1995｜RISC / Cache —— 访存延迟成为一等公民

- **跃迁**：流水线 + 寄存器堆 + 存储层次，把单核性能从「每周期几条指令」推向「每周期一条」
- **影响**：**内存墙雏形出现**；CISC 与 RISC 之争最终以「x86 靠兼容 + 制程红利、ARM 靠授权模式」各占一边收敛
- **结论**：**生态模式比指令集本身更决定胜负**

### 4 · 1995–2006｜多核 / SMP —— 并发成为通用能力

- **跃迁**：单核提速撞上功耗与频率墙，产业转向横向扩展；内存与缓存必须按 NUMA 拓扑手工摆放
- **影响**：软件栈被迫大规模重写，**线程、锁、内存序、并行算法**成为工程师通用技能；Amdahl 定律成为架构与算法的共同天花板

### 5 · 2006–2015｜GPU / CUDA 与移动 SoC —— 竞争焦点转移

- **跃迁**：图形流水线变成通用并行阵列；手机 SoC 用制程与封装红利让消费级设备算力超过桌面
- **影响**：NVIDIA 从「卖显卡」转型「卖算力平台」，**CUDA 成为比指令集更硬的护城河**；软件竞争焦点从 ISA 转向「编程模型 + 库」；计算重心整体移向移动，催生移动优先的互联网与云端数据流

### 6 · 2016–2022｜数据中心专用化 —— 全栈竞赛

- **跃迁**：Transformer + 大规模集群让「专用加速器 + 高速互连」成为标配，云厂商开始自研 ASIC
- **影响**：算力竞赛从芯片级升级为**系统、网络、机房、电力**级的全栈竞赛；模型能力第一次可被资本化，AI 从研究议题变成产品议题

### 7 · 2023–2026｜内存墙 / Chiplet / AI 工厂 —— 瓶颈换人

- **跃迁**：算力两年翻 3 倍，内存带宽只涨 1.6 倍、互连只涨 1.4 倍 —— **大部分算力在等数据**。于是 HBM 容量、KV Cache 分层、prefill/decode 分离成为一等设计
- **影响**：**衡量指标从 FLOPS 转向「每瓦每秒 token」**；推理在 2028 年前后成为数据中心最大电力消耗来源；自研芯片打破单一供给；内存超级周期直接改写消费电子成本结构
- **来源**：Gholami et al. (2024)

### 8 · 2026→｜RISC-V 与可定制异构 —— ISA 从商品变底座

- **跃迁**：2026 年 6 月落地的服务器平台规范 1.0 补齐 UEFI/ACPI、PCIe/IOMMU、BMC Redfish、RAS、安全启动等系统级规则，**让「一套镜像跨品牌部署」成为可能**
- **影响**：新壁垒从「能不能做」转向「**指令扩展碎片化 + 软件生态碎片化 + 产能**」；AI 反哺 ISA 迁移 —— 用 Agent 写移植代码，正在降低换架构的成本

## 每次跃迁带来什么新技术

上面八节讲的是「发生了什么变化」。这张表讲的是另一件事：**哪几样东西是这一轮才第一次存在的** —— 它们之前不存在，后来成了后面所有工作的地基。

| # | 跃迁 | 这一轮才出现的技术 | 首次落点 |
|---|---|---|---|
| 1 | 电子管 / 晶体管 | 存储程序、条件跳转、编译器概念、地址总线、晶体管 | 指令集与微架构 |
| 2 | 集成电路 / ISA 商业化 | 硅片集成、微处理器（4004）、商业 ISA、向后兼容、分时系统 | 指令集与微架构 → 系统与调度 |
| 3 | RISC / Cache | 流水线、寄存器堆、多级 Cache、存储层次、TLB | 指令集与微架构 → 内存与存储 |
| 4 | 多核 / SMP | 多核 SoC、NUMA、一致性协议、内存屏障、SMT | 指令集与微架构 → 内存与存储 |
| 5 | GPU / CUDA 与移动 SoC | 通用并行计算、SIMT、CUDA 库、异构 SoC、FinFET | 指令集与微架构 → 运行时与框架 |
| 6 | 数据中心专用化 | Transformer、矩阵加速器、NVLink / InfiniBand、集合通信、容器编排、低精度训练 | 指令集与微架构 → 系统与调度 |
| 7 | 内存墙 / Chiplet / AI 工厂 | HBM4、Chiplet、KV Cache 分层、prefill/decode 分离、推测解码、液冷 | 内存与存储 → 应用与工作负载 |
| 8 | RISC-V 与可定制异构 | 开放 ISA、服务器平台规范、域专用加速器、自定义扩展、AI 辅助移植 | 指令集与微架构 → 全链重排 |

**「首次落点」是这张表的重点**：八轮里有六轮是从最底层（指令集与微架构）起手的，只有一轮（跃迁 7）是从内存层起手的。起手层决定了后面传导的形状。

## 新技术如何一层层传递

每一轮的技术都不止停在一层。它落在底层，然后**逐层向上改写**；每一层都必须改到位，中间环节才接得住。

### 1 · 存储程序 —— 自下而上贯通型

```
存储器（同构存储） → 总线（寻址） → 指令（取指-执行循环）
   → 编译器（抽象机器） → 应用（可复制的程序）
```

存储器先把程序和数据放在一起（内存层），总线让 CPU 取得到它们（互连层），指令集给出取指-执行循环（指令层），编译器把「机器」抽象掉（运行时层），最后应用层才可能有「可复制的程序」这回事。**任何一层缺席，这条链都断** —— 这也是为什么 1945–1957 被称为「根源期」。

### 2 · ISA 成为契约 —— 自下而上贯通型

```
微处理器（CPU 可采购） → 标准化总线 → 操作系统 → 编译工具链 → 商业软件
```

集成度提升让 CPU 从「整机里最难造的部分」变成一个可买到的元器件（硅层）；总线标准化让不同厂商的主板能互插（互连层）；操作系统成为兼容性的执行者（系统层）；编译器与标准 C / UNIX 让「可移植」成为价值主张（运行时层）；最终受益的是应用层 —— **所有旧软件继续跑**。

注意收益与成本的分层：**收益在应用层，成本在指令层与系统层**。这是本项目「稀缺迁移」的一个微观样本。

### 3 · 流水线与 Cache —— 边界外移型

```
频率竞赛 → 访存延迟暴露 → 内存墙 → 缓存层次化 → 编译器重排 → 应用重写数据结构
```

硅层用面积换缓存，内存层被逼出分层（Cache / DRAM），指令层用超标量与乱序掩盖延迟，系统层要维护页表与 TLB，运行时层靠编译器重排与预取争取时间，应用层最终必须重写数据布局与算法。

**这一轮第一次改变了「优化」的含义**：从「少执行指令」变成「少等数据」。延迟从此成为一等公民。

### 4 · 多核 —— 边界外移型（对象换成软件栈）

```
功耗墙 → 频率封顶 → 横向扩展 → NUMA 拓扑 → 内存序 → 并发编程
```

硅层撞上功耗密度墙，指令层改用多核与 SMT，内存层被迫按拓扑摆放（NUMA），互连层要处理核间一致性，系统层调度必须感知拓扑，运行时层补上语言的内存模型，**应用层第一次被迫大规模重写** —— 线程、锁、内存序成为通用技能。

**这一轮最狠的地方**：技术债没有消失，它从硬件内部搬到了软件栈的第一行代码。

### 5 · GPU / CUDA —— 横向替换型

```
图形流水线可编程化 → SIMT 并行核心 → GDDR 高带宽显存 → CUDA 驱动栈 → cuDNN 库 → 深度学习应用
```

这一轮不是在 CPU 旁边**替换**一条路，而是在应用层**新增**一条路：中间层（驱动、库、调度）为它单独建了一套栈。GPU 核心按「吞吐优先、延迟不敏感」设计（指令层），显存按带宽而非延迟设计（内存层），驱动栈成为一等工程（系统层），编程模型与库成为竞争焦点（运行时层），深度学习成为第一个吃满它的杀手级应用（应用层）。

**结论：生态模式比指令集本身更决定胜负。** CUDA 的真正产品不是 GPU 编程接口，而是「换硬件 = 换生态」这条规则的制造者 —— 它把迁移成本抬到了硬件价格之上。

### 6 · 数据中心专用化 —— 横向替换型（再叠一层）

```
Transformer → 矩阵加速器 → HBM + 高速互连 → 集合通信 → 容器编排 → 机架整柜 → 大模型产品
```

算法层先变，才有专用化的理由（矩阵单元）；加速器逼出高带宽内存与高速互连（内存层 + 互连层）；集群逼出集合通信与拓扑感知调度（系统层）；规模逼出机架整柜与液冷（硅封装层）；运行时层把训练拆成分布式框架（应用层）。

**这一步改变了采购单元**：从「买几颗芯片」变成「买多少机架、多少电」—— 基础设施与 FinOps 从此成为独立角色。

### 7 · AI 工厂 —— 自上而下倒逼型

```
推理变成主负载 → 每次调用都要付钱 → 指标换成每瓦每秒 token
   → 调度器变成产品 → KV Cache 分层与 PD 分离 → HBM 容量成为最紧资源
   → 内存超级周期改写消费电子成本
```

**这一轮传导方向反转了**：不再是底层技术往上推，而是应用层的商业压力**倒逼**最底层。推理成为主负载（应用层）→ 成本直接决定商业模式 → 于是调度器、缓存分层、批处理策略全部变成产品本身（运行时层）→ 电力与排队进入调度（系统层）→ 最终发现真正卡脖子的是 HBM 容量与带宽（内存层），而这是整条链上最难改的一环。

算力两年翻 3 倍，内存带宽只涨 1.6 倍、互连只涨 1.4 倍 —— **大部分算力在等数据**。

### 8 · RISC-V 与可定制异构 —— 契约重排型

```
开放 ISA → 平台规范（UEFI/ACPI、PCIe/IOMMU、BMC Redfish、RAS、安全启动）
   → 一套镜像跨品牌部署 → 应用层最后迁移
```

这一轮动了最底层的契约，而**向上每一层都建立在对既有语义的依赖上**。所以顺序必须反过来：**先把系统层的规则标准化（固件、IOMMU、运维接口），才谈得上应用迁移**。指令层变成可加扩展的底座，硅层走向定制与 Chiplet 组合，互连层解绑单一供应商，系统层拿到标准运维，运行时层负责多版本二进制与扩展调度，应用层最后迁 —— 而这一步的成本，正被 AI 辅助移植压低。

**这一轮的结构与跃迁 1 完全同构**：先补系统层，再让应用层动。

## 传导的四种模式

| 模式 | 跃迁 | 特征 | 代价 |
|---|---|---|---|
| **自下而上贯通型** | 1、2、8 | 底层先立规矩，上层逐层接住 | 任何一层缺席，整条链断 |
| **横向替换型** | 5、6 | 不替换旧路，在应用层新增一条路，中间层单独建栈 | 生态碎片化、迁移成本高 |
| **自上而下倒逼型** | 7 | 应用层的钱倒推最底层的物理约束 | 瓶颈落在最难改的一环 |
| **边界外移型** | 3、4 | 优化的对象从 CPU 内部搬到软件栈 | 技术债换一层楼继续住 |

## 从底层往上看：整条逻辑

把八次跃迁与七层栈压成一张图读：**底座是最硬的物理约束，每往上一层就解放一样东西，同时往物理层压下一份新的稀缺。**

（金字塔的纵轴是「被解放的顺序」，不是职责高度 —— 它把七层栈归并成四段台阶，最下面那段的物理部分（硅、内存、互连）留在基座里。）

| 台阶（自下而上） | 发生在 | 向上交付了什么 | 新稀缺压给了 |
|---|---|---|---|
| 指令集与微架构 | 跃迁 1–3 | 不用再手写机器指令 | 硅与工艺 —— 沉到基座 |
| 运行时与框架 | 跃迁 4–5 | 不用再手写并行与 GPU 底层 | 内存与带宽 —— 沉到基座 |
| 系统与调度 | 跃迁 6 | 不用再手管集群与机器 | 电力与机架 —— 沉到基座 |
| 应用与工作负载 | 跃迁 7–8 | **执行环节可以交出去** | **信任与责任 —— 压不下去** |
| 尖顶 | —— | —— | **目标与责任，仍在人手里** |

**这套结构里最关键的不对称**：前三层解放掉的稀缺，最终都沉到物理层（硅、内存、电力、互连）—— 那是架构层面最难改的地方；而最上面一层解放掉的「执行」，压下去的信任与责任**沉不到物理层去**，它停在人身上。

所以「执行变便宜」不等于「问题解决了」。**执行交出去之后，稀缺只是换了宿主：从机器换成了人。**

这正是 [04 第四次工业革命](04-第四次工业革命.md) 所说的稀缺转移：**目标该由谁设定、结果该由谁负责、出了事谁担责。**

> 视觉版见 [04 底层架构](../visualization/04-architecture.html) 的「从物理约束到目标与责任」一节。

## 台阶放大：指令集与微架构内部（跃迁 1–3）

每段台阶内部都是同一个结构：**每次跃迁各自带来新技术、各自改一条规则、各自往下面压一份稀缺、各自往上面交一份能力。**

| 跃迁 | 带来的新技术 | 改变了什么规则 | 压给下面 | 交付给上层 |
|---|---|---|---|---|
| **3 · RISC / Cache**（1985–1995） | 流水线 · 寄存器堆 · 多级 Cache · 存储层次 · TLB | 性能优化从「少执行指令」转向「少等数据」 | 访存延迟 → 内存墙 | 性能靠喂饱流水线 |
| **2 · ISA 商业化**（1958–1978） | 硅片集成 · 微处理器（4004）· 商业 ISA · 向下兼容 | 兼容性的价值长期高于架构的先进程度 | 集成度与制程 | 软硬件解耦，可移植 |
| **1 · 电子管 / 晶体管**（1945–1957） | 存储程序 · 条件跳转 · 编译器概念 · 地址总线 · 晶体管 | 「程序」成为可存储、可复制、可分发的独立对象 | 晶体管小型化 | 一台机器跑不同程序 |

**台阶 1 对外只兑现一件事：不必自己写指令** —— 一套稳定的 ISA 契约 + 可存储的程序 + 可隐藏延迟的存储层次。

**台阶 1 对下只压两样东西：硅与工艺 · 内存与带宽。** 这里有个转折：跃迁 1、2 压的都是**硅与工艺**，而**跃迁 3 压的却是访存延迟** —— 这一次换了靶子，才有了后来「内存墙」这个说法。

> 视觉版见 [04 底层架构](../visualization/04-architecture.html) 的「台阶放大」一节。

### 台阶二 · 运行时与框架（跃迁 4–5）

| 跃迁 | 带来的新技术 | 改变了什么规则 | 压给下面 | 交付给上层 |
|---|---|---|---|---|
| **5 · GPU / CUDA**（2006–2015） | 通用并行计算 · SIMT / PTX · CUDA 库 · 异构 SoC · FinFET 制程 | 竞争焦点从指令集转到「编程模型与库」；迁移成本由生态决定 | 显存带宽与制程封装 | 并行算力变成可调用的库 |
| **4 · 多核 / SMP**（1995–2006） | 多核 SoC · NUMA 拓扑 · 一致性协议 · 内存屏障 · SMT | 顺序代码不再够用，并发成为默认能力 | 核间互连与访存一致性 | 横向扩展的算力 |

**台阶 2 对外只兑现一件事：不必自己写并行** —— 并发与 GPU 的复杂度被框架和库吸收。

**台阶 2 对下压两样：内存带宽与互连 · 制程与封装。** 靶子从跃迁 4 的**核间互连与一致性**，换到跃迁 5 的**显存带宽** —— 算力堆得快，带宽跟不上。

### 台阶三 · 系统与调度（跃迁 6）

| 跃迁 | 带来的新技术 | 改变了什么规则 | 压给下面 | 交付给上层 |
|---|---|---|---|---|
| **6 · 数据中心专用化**（2016–2022） | Transformer · 矩阵加速器 · NVLink / InfiniBand · 集合通信 · 容器编排 · 低精度训练 | 竞争焦点从芯片级升级为系统、网络、机房、电力级的全栈竞赛 | 机架功率密度与电力 | 集群与调度不必自己管 |

**台阶 3 对外只兑现一件事：不必自己管集群** —— 机器、容器、拓扑、调度都交给编排系统。

**台阶 3 对下压两样：电力与机架 · 高速互连。** 采购单元从「买几颗芯片」变成「买多少机架、多少电」，交付单元已是机架，FinOps 成为独立角色。

### 台阶四 · 应用与工作负载（跃迁 7–8）

| 跃迁 | 带来的新技术 | 改变了什么规则 | 压给下面 | 交付给上层 |
|---|---|---|---|---|
| **8 · RISC-V 与可定制异构**（2026→） | 开放 ISA · 服务器平台规范 1.0 · UEFI/ACPI · PCIe/IOMMU · BMC Redfish · RAS · 安全启动 · 自定义扩展 | ISA 从商品变底座；新壁垒是指令扩展碎片化 + 软件生态碎片化 + 产能 | 产能与流片成本 | 一套镜像跨品牌部署 |
| **7 · 内存墙 / AI 工厂**（2023–2026） | HBM3E → HBM4 · Chiplet · 液冷 · KV Cache 分层 · prefill/decode 分离 · 推测解码 | 衡量指标从 FLOPS 转向「每瓦每秒 token」；推理成为主负载 | HBM 容量与带宽 | 执行环节可以交出去 |

**台阶 4 对外只兑现一件事：执行可以交出去。**

**但它是唯一一段稀缺没有全部沉到基座的台阶**：跃迁 7 把 HBM 容量与带宽沉到基座，跃迁 8 把碎片化散进生态，而「信任与责任」压不下去 —— 它留在人身上，就是金字塔尖顶那一句。

### 四段台阶对照

| 台阶 | 跃迁 | 对上兑现 | 对下压给基座 |
|---|---|---|---|
| 一 · 指令集与微架构 | 1–3 | 不必自己写指令 | 硅与工艺 · 内存与带宽 |
| 二 · 运行时与框架 | 4–5 | 不必自己写并行 | 内存带宽与互连 · 制程与封装 |
| 三 · 系统与调度 | 6 | 不必自己管集群 | 电力与机架 · 高速互连 |
| 四 · 应用与工作负载 | 7–8 | **执行可以交出去** | HBM 容量与带宽 · 电力（**信任与责任压不下去，留在人身上**） |

## 技术架构路线：六条维度 × 五个阶段

台阶是纵切面；这一张是横切面 —— 同一条时间轴上，六条技术维度各自怎么被替代，以及每个阶段真正卡住大家的是哪一样。

| 维度 | 1945–1995<br>奠基期（1–3） | 1995–2015<br>并行期（4–5） | 2016–2022<br>专用化（6） | 2023–2026<br>AI 工厂（7） | 2026→<br>前方（8 途中） |
|---|---|---|---|---|---|
| **逻辑部件与封装** | 电子管 → 晶体管 → 集成电路 → VLSI | 制程红利 · FinFET · 多核 SoC 单片集成 | 矩阵加速器 · 专用 ASIC | Chiplet + 先进封装 · 液冷 | 定制化 · 域专用加速器（方向已明，形态未定） |
| **互连** | 地址总线 → 标准化总线 | 片上互连 · NoC · NVLink | InfiniBand / RoCE · Scale-up 成型 | UBB · 光互连 | PCIe / IOMMU 标准化（服务器平台规范 1.0） |
| **存储层次** | 磁芯 → 半导体 · Cache/DRAM 分层 | NUMA 拓扑 · GDDR 与 DDR 分叉 | HBM + 并行文件系统 | HBM4 · KV Cache 分层 | **？尚未定位** |
| **执行与并发模型** | 单指令流 → 流水线 → 超标量 | 多核 / SMP → SIMT | 集合通信 · 分布式训练 | 推理服务 · Agent 编排 | **？尚未定位** |
| **编程模型与生态** | 机器码 → 汇编 → 编译器 · 标准 C | 线程与内存模型 → CUDA 与库 | 分布式训练框架 | vLLM / SGLang · 兼容层 | 多版本二进制 · AI 辅助移植（碎片化尚未收敛） |
| **规模与交付单元** | 单机 → 工作站 | 多核 SoC → 机群 | 机架（整柜交付） | AI 工厂 | **？尚未定位** |
| **互联网与云** | ARPANET → TCP/IP → 万维网 | 宽带 · Web 2.0 · 云计算 | 数据中心成为云的底座 · 流媒体规模化 | 模型即服务经互联网分发 · Agent 工具协议 | **？尚未定位** |
| **移动设备** | 蜂窝电话 · 2G GSM | iPhone（2007）触屏 + App 生态 · 4G | 5G · 移动成为主入口 | 端侧模型 · 端云协同 · 手机作为 Agent 终端 | **？尚未定位** |
| **半导体与封装** | 晶体管 → 平面工艺 → 光刻 → 集成电路 / VLSI | 深亚微米 · 铜互连 · FinFET · 存储器缩放 | EUV 量产 · HBM · CoWoS · Chiplet | GAA · High-NA EUV · HBM4 · 先进封装 | 定制化 · 域专用 · 三维堆叠（形态未定） |
| **通信与光互连** | 铜缆 → 同轴 → 光纤 | 光骨干网 · 2G/3G/4G · 宽带与蜂窝 | 硅光 · 400G/800G 光模块 · 数据中心光互连 | CPO 共封装光学 · 1.6T · 低轨卫星 | **？尚未定位** |
| **能源与散热** | 风冷 · 机房级供电 | 冷冻水 · 机柜 10–20kW | 数据中心电力集中化 · 30kW 级机柜 | 冷板液冷为主 · 100kW+ 机柜 · 变电与选址成为约束 | 浸没式与液冷路线未定 |
| **主导瓶颈（计算）** | 指令吞吐 → 访存延迟 | 访存延迟 → 互连带宽 | 互连带宽 → 内存容量与带宽 | 内存容量与带宽 → 电力与成本 | **？下一轮主导瓶颈未确定** |
| **主导瓶颈（连接与接入）** | 接入稀缺（拨号与许可） | 带宽稀缺（骨干网与 CDN） | 流量与分发稀缺（视频流） | 入口与注意力稀缺（超级 App） | **？未确定** |
| **主导瓶颈（物理层）** | 器件与工艺 | 互连延迟与漏电 | 封装产能与光模块产能 | 电力与散热 | **？未确定** |

### 前方：已确认的三条方向

- 开放 ISA 的服务器平台规范落地（2026-06），互连与固件层开始标准化
- 定制化与 Chiplet 成为交付主流
- 推理主导负载后，「每瓦每秒 token」取代 FLOPS 成为核心指标

### 前方：还没定位的四件事

1. 下一轮主导瓶颈落在哪一层
2. 下一轮的技术跃迁发生在哪一层
3. 指令扩展与软件生态的碎片化最终收敛还是加剧
4. 存储层次上会出现什么新的约束

> 这四条目前都没有足够依据，图中一律留空并标「尚未定位」，不猜。

> 视觉版见 [04 底层架构](../visualization/04-architecture.html) 的「技术架构路线」一节。

## 贯穿其中的规律

**每次跃迁都在解决上一轮的瓶颈，而复杂度同步上移一层：**

| 跃迁 | 逼出来的下一层复杂度 |
|---|---|
| 多核 | 并发编程（线程、锁、内存序） |
| GPU / CUDA | 编程模型与库生态 |
| 数据中心专用化 | 分布式一致性 |
| AI 工厂 | 调度与成本治理 |

> **技术债不会消失，只会换一层楼继续住。**

**瓶颈下沉方向**（从抽象层看）：

```
S1–S3  指令与流水线     →  S4–S5 并行与编程模型
S6     互连与集群       →  S7 内存容量与带宽
S8     电力 / 成本 / 生态
```

越往下越难改，但越往上越能藏 —— 这就是为什么芯片、内存、网络的代际变化会直接改写应用架构。
