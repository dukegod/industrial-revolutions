04 · Architecture & Impact

七层抽象栈，与它带来的结构性改变

这是第三次革命内部的纵切面。第三次革命在「计算」这一个维度上的进程是八次架构跃迁（见 03 第三次），这一页把它们压缩成七层抽象栈、三条主线与一张逐层传递矩阵——看每一层如何解决上一层的麻烦，又制造了什么新麻烦。

01

先看栈：瓶颈在层与层之间往下沉

抽象层越高，越容易把复杂度「藏起来」

每一次架构跃迁，本质上都是把某一层的复杂度用软件吸收掉，同时把新的稀缺性压到更低层。 上层开发者感受最直接的，往往是最低层的改动——这就是为什么芯片、内存、网络的代际变化会直接改写应用架构。

02

从物理约束到目标与责任：一张图看完整个逻辑

稀缺下沉 · 能力上浮

图 1 是按职责把系统拆成七层。这张图换一种读法：按被解放的顺序把七层归成四段台阶。 每一段台阶做的是同一件事 —— 把下一段的复杂度用软件吸收掉，向上交付一层能力，同时把一份新的稀缺压给下面。

能力上浮：四段台阶

指令层 → 运行时层 → 系统层 → 应用层，越往上越晚被解放。到最上面一段，「执行」这件事第一次可以整个交出去。

稀缺下沉：一份也没消失

硅与工艺 → 内存与带宽 → 电力与机架 → 信任与责任。每层吸收了下一层的复杂度，就把自己的麻烦压下去。只有最后一份压到了人身上。

尖顶那句「目标与责任」，展开就是 第四次工业革命： 执行变便宜之后，稀缺就转向「谁定义目标、谁验收结果、谁担责」。

03

把八段历史压缩成三条主线

记住这三条，就抓住了演进的骨架

主线一的代价

每次「解决瓶颈」的做法都是把复杂度推向上一层：多核逼出并发编程，GPU 逼出编程模型与库，集群逼出分布式一致性，AI 工厂逼出调度与成本治理。技术债不会消失，只会换一层楼继续住。

主线二的代价

专用化换来效率，代价是生态碎片化：CUDA 锁住生态，RISC-V 面临各家自定义扩展互不兼容。判断新架构的成熟度，看的不是峰值参数，而是「一套镜像能不能跨品牌部署」。

04

技术如何一层层传递

八次跃迁 × 七层栈

每次跃迁的技术都不止停在一层。它落在底层，然后逐层向上改写；每一层都必须改到位，中间环节才接得住。 下表是八次跃迁在七层栈上的落点——横向读是一次跃迁的传递路径，纵向读是每一层被解放的顺序。

自下而上贯通型

跃迁 1、2、8。底层先立规矩，上层逐层接住。任何一层缺席，整条链就断——1945 年的存储器与总线、2026 年的固件与 IOMMU 规范，都站在这个位置上。

横向替换型

跃迁 5、6。不替换旧路，而是在应用层新增一条路，中间层为它单独建栈（驱动、库、调度）。代价是生态碎片化与迁移成本——CUDA 把迁移成本抬到了硬件价格之上。

自上而下倒逼型

跃迁 7。传导方向反转：应用层的商业压力倒逼最底层。「每次调用都要付钱」把调度器变成产品，把 HBM 容量变成整条链上最难改的一环。

边界外移型

跃迁 3、4。优化的对象从 CPU 内部搬到软件栈：从「少执行指令」变成「少等数据」，再变成「少写并发代码」。技术债不会消失，只会换一层楼继续住。

逐跃迁的完整传递链与判断依据，见 wiki 条目 06 电子计算机八次跃迁； 具体数据与来源见 现状与来源页。

05

带来的影响：十个维度的结构性改变

架构变了什么 → 谁买单
架构变化改变的规则谁最先感受到
存储程序 + 通用机 「程序」成为可存储、可复制、可分发的独立对象 整个软件产业从第一天起就存在
ISA 商业契约 + 向下兼容 兼容性的价值长期高于架构的先进程度 PC 生态三十年格局；也埋下 x86 的路径依赖
Cache / 存储层次 性能优化从「少执行指令」转向「少等数据」 所有延迟敏感型服务（数据库、推理、在线系统）
多核 / SMP 顺序代码不再够用，并发成为默认能力 后端与基础设施团队；也是分布式系统的起点
GPU + CUDA 生态 竞争焦点从指令集转到编程模型与库；迁移成本由生态决定 算法与平台团队（换后端 = 换生态，不是换硬件）
数据中心专用化 采购与优化单元从「芯片」变成「集群 / 机架 / 电力」 基础设施与 FinOps：TCO 模型整体重写
HBM4 + Chiplet + 液冷 成本结构从「算力成本」转向内存 + 电力 + 互联三元组 推理服务方与平台成本治理
RISC-V + 可定制 指令集从商品变底座，差异化能力转向定制与系统集成 芯片设计方；软件方面临新的碎片化风险
推理成为主负载 从「训练一次、用无数次」变成「每次调用都要付钱」 产品形态：成本直接决定商业模式能否成立
Agent 负载结构 算力密集 ＋ 控制密集 ＋ I/O 密集并存 Agent 平台：CPU/GPU 分池与资源画像成为一等能力
